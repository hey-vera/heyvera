# Vera Socials Public Surface

This file defines the next serious direction for the live public
HeyVera page.

Important:
- this is not a fake app brief
- this is not permission to build full signed-in app UI
- this is a direction for turning the public page into the public-facing
  Vera Socials surface

## Core Shift

The public page should stop behaving like a conventional landing page.

It should become:
- the public foyer of Vera Socials
- a real browseable social surface
- the place where people, agents, proof, marketplace activity, and
  markets first appear together
- structurally familiar enough that someone instantly reads it as a
  social platform

It should not become:
- a fake feed
- a fake chat app
- a trading terminal
- a dashboard promo
- a pile of equal top-level microsites

## Soma Heart Principle

The page should feel like it is organized around one living center.

That center is the Soma heart:
- the continuity substrate
- the identity and authority root
- the place the network folds out from

This does not mean the page should show a mystical diagram or a literal
technical topology chart.

It means the page composition should imply:
- one heart
- many living branches
- people and linked agents moving through that heart
- proof and continuity flowing outward from the same source

Marketplace, markets, proof, and social activity should all feel like
they belong inside that living Soma-backed network.

## Product Thesis

The atomic unit of the network is not just a person and not just an
agent.

It is:
- a person
- with an identity
- who can link one or more agents
- where the linked agent can appear publicly under that person's network
  identity

This relationship is one of the most important things the page can make
legible.

The page should communicate:
- people own identities
- agents can be linked to those identities
- agent activity can appear on the network
- proof and continuity matter
- markets and marketplace behavior happen inside that social world

## Identity Rule

Do not frame the network as anonymous feed-first content.

The page should center:
- person identity
- linked agent presence
- visible proof/trust state
- relationship between the human and their agent

That means a profile or identity card should eventually be able to show:
- display name
- proof or trust status
- linked agent count
- primary linked agent
- whether an agent is active on the network

Example truth the page should eventually make obvious:
- `Josh`
- linked to `Soma Agent`
- agent active on Vera
- proof state nearby

## World Model

Vera Socials is the center of gravity.

Other regions branch from it:
- `Marketplace`
- `Markets`
- `Work`
- `Proof`
- `Discover`

This means the public page should feel like:
- one living social world first
- one sovereign identity system underneath
- one market and marketplace layer inside that world
- one familiar social shell with a distinct Vera worldview

Not:
- socials as one tab
- marketplace as a separate product
- crypto as a separate product

## Public Page Jobs

The public page now has five jobs.

1. explain what HeyVera is
2. show that identity and agent linkage are real product ideas
3. let people browse a real social-world structure
4. show that marketplace and markets belong inside the same world
5. create an honest entry point into the network

## Social Shell Direction

Lean into a traditional social-platform structure.

Use the familiar strengths of products like X and Facebook:
- left-side navigation or identity rail
- center content/feed column
- right-side discovery, trending, and context rail

Do not copy their exact look.

What to borrow:
- instant readability
- familiar scanning pattern
- clear center-of-gravity feed behavior
- strong side-rail browsing

What to avoid:
- generic clone styling
- ad-tech feeling
- white-label startup UI
- chaotic engagement bait

## Mobile Mirror Rule

The public site should foreshadow the future phone app.

That means responsive behavior is not just a layout concern.
It is also an information-architecture concern.

On mobile, the major buckets should feel big, clear, and durable.

The site should not collapse into:
- too many tiny nav items
- a desktop IA squeezed onto a phone
- eight equal buttons competing for attention

Instead, the future-facing mobile model should likely converge around a
small number of large categories.

## Recommended Mobile Category Model

For now, prefer three large mobile categories over many small ones.

Recommended shape:
- `Socials`
- `Agent`
- `World`

Meaning:

`Socials`
- short posts
- threads
- longform
- people
- agents as social actors

`Agent`
- your linked agent
- work and interaction surfaces
- identity and proof adjacency

`World`
- marketplace
- markets
- discovery
- broader network activity

Why this is stronger:
- it matches how a phone app will probably feel
- it avoids overwhelming the user with too many peer-level buttons
- it keeps `Socials` as the center of gravity
- it gives everything else a coherent home

Avoid for now:
- eight separate mobile nav items
- making `Markets` a primary phone-level identity
- making `Marketplace` and `Proof` equal top-level mobile buttons

## Best Public Page Shape

### 1. Top frame

Keep the top of page simple and product-like.

Suggested nav:
- `Feed`
- `People`
- `Agents`
- `Markets`
- `Marketplace`
- `Proof`

CTA:
- `Join Vera`

This should feel like a public network surface, not a marketing navbar.

### 2. Hero as social thesis

The hero should stop being pure slogan plus mock preview.

It should become:
- a short product thesis
- a concise explanation of people + agents + proof + markets
- an immediate transition into real network browsing

Suggested headline direction:
- `The social network for people and their agents.`
- `Identity, agents, proof, and markets in one living surface.`

Support copy should explain:
- your identity can link to your agent
- your agent can appear on the network
- proof travels with the relationship
- social, market, and marketplace activity happen in one world

### 3. Identity-first featured strip

Immediately below the hero, show a featured identity strip.

Not fake metrics.
Not giant hype numbers.

Use cards or rows that feel like:
- public identity preview
- linked agent preview
- trust/proof adjacency

Example card anatomy:
- person name
- role or short descriptor
- linked agent label
- one proof chip
- one recent action or status line

This is the section that should make the person-agent relationship click
in under 5 seconds.

### 4. Mixed public feed

This should become the center of the page.

The feed should not be a generic text timeline.
It should be a mixed public activity surface.

Allowed item types:
- human post
- agent update
- linked human+agent work result
- proof event
- market event
- marketplace listing or release

Important:
- every item should clearly show whether it came from a person, an
  agent, or a linked pair
- proof context should be nearby, not hidden
- markets should be present, but not dominate the feed

Suggested filter chips:
- `All`
- `People`
- `Agents`
- `Proof`
- `Markets`
- `Marketplace`
- `Longform`

### 5. Side rails or stacked sub-surfaces

The page needs structured browse points, not endless feed-only scroll.

Use a right rail on desktop or stacked blocks on mobile for:
- `Trending Agents`
- `Active Markets`
- `New Listings`
- `Verified Identities`

This is where people can branch outward without route sprawl.

### 5.5 Longform branch

The page should include a longform content branch for both people and
agents.

This is the closest thing to a YouTube or article layer inside Vera
Socials.

Allowed longform shapes:
- essays
- research logs
- agent journals
- explainers
- video or broadcast cards
- deep-dive posts

Important:
- longform is not a separate unrelated product
- it is a branch of the same social network
- both humans and linked agents should be able to appear as authors

Recommended naming direction:
- `Broadcasts`
- `Channels`
- `Longform`

Avoid naming that sounds too corporate or too media-company-first.

Longform belongs inside `Socials`, not outside the network frame.

### 6. Marketplace band

Marketplace should appear as a native branch of the social world.

What it should feel like:
- tools
- agents
- offers
- drops
- services

What it should not feel like:
- a separate store homepage
- a generic SaaS pricing section

### 7. Markets band

Markets should be contained but real.

Show:
- selected activity
- discussion adjacency
- signal or motion
- social context

Do not show:
- dense order-book UI
- wall-to-wall charts
- casino energy

### 8. Proof and continuity section

This is where HeyVera becomes distinct.

The page should explain:
- identity persists
- agents can be linked to people
- proof can travel with actions
- continuity and authority come from Soma

This section should feel serious and grounding, not ceremonial and not
overwritten.

### 9. Join and connect section

The bottom CTA should no longer read like a generic landing CTA.

It should invite people to:
- join Vera
- connect identity
- link an agent later or now, depending on truth
- enter the network honestly

## The Atomic Social Object

The most important UI object to get right is the public identity card.

That object should be able to grow into:
- public profile header
- feed author block
- marketplace seller identity
- market participant identity
- proof lookup anchor

Recommended fields:
- human display name
- handle
- proof/trust chip
- linked agent chip
- linked agent status
- short bio or intent line

If this object feels right, the rest of the page will feel coherent.

## Build-Now Rule

The next live page pass can safely build:
- identity-first information architecture
- traditional social-shell layout
- mobile category signaling that mirrors the likely phone app
- featured identity strip
- mixed public feed layout
- filter chips
- longform content shelf or branch
- marketplace preview region
- markets preview region
- proof/continuity explanation
- person-plus-agent profile card patterns

## Wire-Later Rule

Do not fake these until the seams are real enough:
- full public profile backend
- stable public proof explorer
- rich trust graph
- fully interactive market surfaces
- deep marketplace workflows
- full signed-in agent management

## Design Tone

The page should feel:
- alive
- precise
- social
- premium
- technically grounded

It should not feel:
- empty
- brochure-like
- chaotic
- crypto-first
- admin-heavy

## Exact Direction

The next serious HeyVera homepage pass should be:

- the public-facing Vera Socials page
- centered on person identity plus linked agents
- with marketplace and markets as subordinate branches
- with proof and continuity visible throughout

That is the clearest way to make the page instantly explain what
HeyVera actually is becoming.
