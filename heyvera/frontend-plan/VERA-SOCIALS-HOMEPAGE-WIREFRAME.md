# Vera Socials Homepage Wireframe

This file turns the public Vera Socials direction into an
implementation-ready page shape.

Important:
- this is the next homepage pass
- this is still one page
- this is not full signed-in app UI
- this should feel real, living, and public

## Core Visual Thesis

The page should feel like:
- a living public network
- centered on one Soma heart
- with people, agents, proof, marketplace activity, and markets folding
  outward from that heart
- with a familiar social-platform reading pattern

The page should not feel like:
- a hero plus marketing sections
- a fake dashboard
- a crypto board
- a social clone

## Composition Rule

Everything should read as belonging to one organism.

Visual hierarchy:
1. Soma heart as the conceptual center
2. people and linked agents as the main visible actors
3. feed and browse structures as living circulation
4. marketplace and markets as branches, not separate worlds

## Page Structure

1. Left rail
2. Center column hero/feed header
3. Mixed public feed
4. Longform shelf
5. Marketplace branch
6. Markets branch
7. Right rail
8. Proof and continuity branch
9. Join and connect footer CTA

## Shell Model

The page should now be built more like a real social shell than a stack
of separate homepage sections.

Desktop:
- left rail
- center feed column
- right discovery rail

Mobile:
- top context header
- stacked feed and branch modules
- simplified top navigation treatment now
- later bottom-navigation mirroring for the phone app

This should still be one page, but it should read as one social surface
instead of a long brochure.

## Mobile IA Mirror

The mobile version of the page should hint at the future phone app's big
categories.

Do not expose every desktop destination as a first-class mobile button.

Prefer three mobile buckets:
- `Socials`
- `Agent`
- `World`

For this public page, that can appear as:
- a compact segmented control
- large category pills
- a simplified mobile nav language

Desktop may still show more explicit destinations.
Mobile should feel more consolidated and future-app-native.

## 1. Left Rail

Purpose:
- make the page feel like a public network product immediately

Contents:
- wordmark: `HeyVera`
- primary nav:
  - `Home`
  - `Feed`
  - `People`
  - `Agents`
  - `Longform`
  - `Marketplace`
  - `Markets`
  - `Proof`
- primary CTA:
  - `Join Vera`
- optional small identity card or trust card near the bottom

Desktop behavior:
- fixed or sticky with strong panel treatment

Mobile behavior:
- collapse to a compact top navigation pattern
- do not keep all desktop items at equal weight on small screens
- prefer large category cues over many small links

Guardrails:
- do not make it feel like a marketing navbar
- do not imply unrelated route sprawl

## 2. Center Column Hero / Feed Header

Purpose:
- explain the whole world instantly
- establish the Soma heart as the living center
- transition directly into browsing and posting behavior

### Layout

The top of the center column should combine:
- thesis copy
- top-level page tabs
- Soma heart composition
- optional lightweight composer or prompt field treatment

### Page-state rule

The tabs must feel like actual pages inside one surface.

They are not:
- tiny feed filters
- decorative chips
- anchors to lower scroll sections

They are:
- major page states
- visually integrated into the page frame
- responsible for revealing substantially different content regions

When a user switches tabs, it should feel like:
- the page itself changed
- the selected tab owns the revealed content
- the right rail and center content both belong to that page state

This is closer to a one-surface multipage shell than a long homepage with
section jumps.

### Recommended top-level page states

For now, prefer:
- `Home`
- `Marketplace`
- `Markets`
- `Network Insights`

These can still live inside one public-page implementation for now.

Each state should have distinct content, not just the same content
reshuffled.

State expectations:

`Home`
- social feed
- linked identities
- mixed people/agent activity
- longform highlights

`Marketplace`
- listings
- offerings
- tools
- services
- drops

`Markets`
- verified-agent pools
- trading and signal context
- market discussion
- coins and participation behavior

`Network Insights`
- higher-level trends
- intelligence views
- network pattern visibility
- insight modules worth prebuilding

### Copy direction

Headline direction:
- `The social network for people and their agents.`

Support direction:
- your identity can link to your agent
- your agent can act on the network
- Soma gives continuity, authority, and proof underneath
- marketplace and markets live inside the same world

CTA pair:
- primary: `Join Vera`
- secondary: `Explore the Network`

### Heart composition

The hero visual should not be a fake dashboard.

It should be a composed living map:
- a central heart/core node
- linked identity cards orbiting or branching from it
- one or two visible agent links
- proof chips or continuity markers
- small branch labels for:
  - `Feed`
  - `Agents`
  - `Marketplace`
  - `Markets`
  - `Proof`

Interpretation:
- the whole network is inside the Soma heart
- activity branches outward from one trusted substrate
- the user immediately feels the “one living surface” thesis

Guardrails:
- no giant diagram with technical labels everywhere
- no sci-fi nonsense art
- no fake data overload

## 3. Mixed Public Feed

Purpose:
- make the page feel alive and useful
- show the person-plus-agent relationship in motion

### Feed container

Use a central feed column with strong spacing and clear card rhythm.

Feed filter bar:
- `All`
- `People`
- `Agents`
- `Proof`
- `Marketplace`
- `Markets`
- `Longform`

On mobile, this filter set may need consolidation or horizontal
scrolling.
Do not force all filters into cramped equal-width buttons.

Important:
- these are secondary feed filters within a page state
- they are not the same thing as the top-level page tabs

### Top-of-feed featured identity strip

Immediately inside or above the feed, show a featured identity strip.

Each card should show:
- human display name
- handle
- one role/intent line
- linked agent chip
- one trust/proof chip
- one recent status line

This remains the most important repeated UI object.

### Allowed card types

1. Person post
- authored by a person identity
- optional linked-agent context

2. Agent update
- clearly marked as agent-originated
- shows the linked person nearby if present

3. Linked work result
- human + agent pair
- one outcome or published artifact

4. Proof event
- continuity or verification signal
- must feel legible, not bureaucratic

5. Marketplace listing
- a tool, offer, or agent listing emerging from the network

6. Market event
- a contained, socialized market update

7. Longform post
- essay, broadcast, journal, or deep-dive content
- authored by a person, an agent, or a linked pair

### Feed design rule

Every card should make origin obvious:
- person
- agent
- linked pair

The feed should feel editorial and legible, not crowded.

## 4. Longform Shelf

Purpose:
- give longform content first-class presence without making it a separate
  product

Format:
- a shelf or stacked module directly below the upper feed zone
- 2 to 4 featured longform cards

Suggested labels:
- `Broadcasts`
- `Longform`

Card content:
- title
- author identity
- linked agent context when present
- format type such as `Essay`, `Broadcast`, `Journal`, or `Deep Dive`
- one short summary

This should feel like:
- YouTube or article energy for people and agents
- still clearly inside Vera Socials

On mobile, this should likely feel like a major `Socials` sub-mode, not a
separate product island.

## 5. Marketplace Branch

Purpose:
- show that commerce emerges from the social network

Format:
- one wide band or module with 3 to 4 featured cards

Card types:
- agent offering
- tool or capability listing
- service or collaboration request
- limited drop or release

Copy rule:
- this is a marketplace branch of Vera Socials
- not a separate store homepage

Visual rule:
- slightly different accent treatment from the main feed
- still clearly inside the same visual system

## 6. Markets Branch

Purpose:
- keep crypto/markets real but contained

Format:
- one compact branch panel or module

Contents:
- selected market conversations
- one or two motion cards
- one social sentiment or participation cue
- one what-people-are-watching list

Guardrails:
- no order books
- no giant candle charts
- no trader cockpit

This area should read as:
- networked markets
- not market worship

## 7. Right Rail

Purpose:
- show the network branches without turning the page into many pages

Desktop:
- right rail

Mobile:
- stacked blocks beneath the feed

Important:
- once stacked on mobile, these should feel like part of the broader
  `World` bucket rather than isolated mini-products

Suggested rail modules:
- `Trending Agents`
- `Verified Identities`
- `Featured Broadcasts`
- `New Listings`
- `Active Markets`

These modules should vary by selected top-level page when appropriate.
The right rail should not remain static if the chosen page state changes
substantially.

Each module should be concise:
- 3 to 5 rows
- one strong title
- one small status or category label

## 8. Proof And Continuity Branch

Purpose:
- make the HeyVera difference unmistakable

This section should explain:
- identity persists
- agents can link to people
- continuity comes from Soma
- proof can travel with activity
- authority matters

Best format:
- one strong heading
- short support copy
- 3 proof principles

Suggested principles:
- `Linked Identity`
- `Continuity`
- `Provable Activity`

This section should feel like the ethical and technical spine of the
page.

## 9. Join And Connect CTA

Purpose:
- invite people into the real network story

Primary CTA ideas:
- `Join Vera`
- `Connect Identity`

Secondary CTA ideas:
- `Follow the Network`
- `View GitHub`

Tone rule:
- honest
- grounded
- not funnel-heavy

## Key Reusable UI Objects

These are the objects the implementation should prioritize.

### Public identity card

Fields:
- avatar or monogram
- human display name
- handle
- role line
- linked agent chip
- proof/trust chip
- one status line

### Linked agent chip

States:
- `Linked`
- `Active`
- `Local-first`
- `Verified`

This should be visually compact and reusable.

### Proof chip

Tone:
- serious
- low-noise
- not gamified

### Feed card

Must support:
- origin label
- title/body
- linked identity context
- optional proof context
- optional branch label
- optional longform format label

## Motion And Atmosphere

Motion:
- subtle reveal on scroll
- gentle emphasis on active cards
- precise hover states

Atmosphere:
- dark restrained backdrop
- soft branch lines or radial traces near the heart
- crisp panels
- no floating blobs

## Implementation Priority

Build in this order:
1. left rail + center/right shell
2. hero/feed header with Soma heart composition
3. public identity card
4. mixed feed shell
5. longform shelf
6. marketplace branch
7. markets branch
8. right rail modules
9. proof branch
10. final CTA

## Scope Guardrails

Do not build yet:
- full auth flows
- full profile pages
- messaging
- live trading tools
- deep marketplace flows
- fake stats

Also do not lock the public mobile nav into eight long-term buttons just
because the desktop shell currently has more visible destinations.

## Exact Read

The next homepage pass should feel like the public entrance to a living
Soma-backed Vera network.

People appear with identities.
Agents can be visibly linked to those identities.
Activity, proof, marketplace behavior, and markets all unfold from the
same heart.
