
# Opus — claw-net.org Website Redesign

## Context
The site content and structure are solid. The problem is visual credibility. Right now it looks like a developer side project. It needs to look like infrastructure that enterprises and serious builders trust. The content stays mostly the same — the design, imagery, and visual hierarchy change.

## Reference sites to study for tone
- stripe.com (clean, developer-friendly, professional)
- linear.app (dark, minimal, high-quality)
- vercel.com (developer-focused, great code examples)
- x402.org (simple but credible)

## Guiding principles
1. Dark theme. Keep it. But upgrade from "dark template" to "premium dark."
2. Every visual element must be high-effort. No emoji icons (⚡🔍⚖🛡). Replace with proper SVG icons or recognizable brand imagery.
3. White space is confidence. Cramped = amateur. Generous spacing = "we don't need to cram everything above the fold."
4. Code examples should look real and syntax-highlighted. These are the most important visual element for developers.
5. Social proof through recognizable logos and integrations, not through star ratings.

## Section-by-section redesign

### 1. Hero Section
**Current:** "The operating system for the agent economy" with generic subtitle and two buttons.

**Fix:**
- Keep the headline. It's strong.
- Subtitle is too long. Cut to: "Discover services. Transact. Build reputation. One API."
- Add a real terminal/code snippet below the buttons showing an actual API call and response — not a decorative animation, but real code that a dev can read and understand in 3 seconds
- The stats bar (endpoints live, providers, queries served, avg response) — make these BIG and prominent. Real numbers are credibility. Use a monospace font for the numbers. If the numbers are still small, show what you have honestly. Don't use "—" placeholders.

### 2. "The problem" Section
**Current:** Three cards with emoji numbers (01, 02, 03) and text.

**Fix:**
- Replace the emoji/number indicators with clean minimal SVG icons:
  - No marketplace → a broken/disconnected network icon
  - No accountability → a document with a question mark
  - No reputation → two identical blank agent silhouettes
- Make the icons monochrome (white or a single accent color, not colorful)
- The text is good. Keep it.
- Add subtle dark card backgrounds with a very slight border (1px, rgba white at 10%) to create depth without color

### 3. "One platform" / What ClawNet Is
**Current:** Four features with emoji headers (⚡🔍⚖🛡).

**This is the most important section to fix.** Replace every emoji with a proper icon or visual:

- **Orchestration** → Show a flow diagram: query → router → multiple endpoints → aggregated result. Not decorative — functional. A simple SVG that actually shows the routing concept. Use recognizable protocol logos where applicable (MCP logo, x402 logo).

- **Skill Marketplace** → Show a grid of skill cards (like an app store) with real skill names from your marketplace. Include recognizable data source logos if possible: CoinGecko, DeFiLlama, Birdeye, etc. Whatever your skills actually pull from.

- **Micropayments** → Show the two payment rails visually: credit card icon + Solana/USDC logo on one side, x402 logo on the other. Include the "$0.001 per query" number prominently — that's the hook.

- **Verifiable Trust (Soma)** → This is the differentiator. Show a birth certificate visualization: a card/document graphic with fields like "Source: ClawAPIs", "Hash: 0x7f3a...", "Signed by: did:key:z6Mk...", "Trust tier: single-signed". Make it look like a real cryptographic receipt. Include the Soma logo/wordmark. Link to the paper DOI.

**Under the four features, add an integration bar:** A horizontal strip of logos showing what ClawNet works with. These should be RECOGNIZABLE:
- Protocol logos: MCP, x402, A2A, Solana
- Data sources your skills use: whatever APIs you're pulling from
- Tools: OpenClaw, Claude, etc.

This is what Zauth does well — the Coinbase, Solana, GitHub logos instantly signal "this is real infrastructure." You need the same.

### 4. "How it works" — Four steps
**Current:** Four numbered steps with text only.

**Fix:**
- Turn this into a visual flow. A horizontal pipeline diagram:
  Query → Route → Execute → Bill & Prove
- Each step should have a small illustration (not emoji, not icon — a tiny diagram showing what happens at that step)
- Under each step, show a real code snippet or API response that corresponds to that step. For example:
  - Step 1 (Query): `POST /v1/orchestrate { "query": "SOL price" }`
  - Step 2 (Route): Show the routing decision: `Selected: sol-price-feed (0.8s, 1.5cr)`
  - Step 3 (Execute): Show the result JSON
  - Step 4 (Bill & Prove): Show the birth certificate fields in the response

### 5. "Not a whitepaper. Ship today."
**Current:** Code tabs with curl/JS/Python. Good concept but needs polish.

**Fix:**
- This section is actually close to right. The code examples are the strongest visual element on the site.
- Improve the syntax highlighting. Use a proper code theme (One Dark, Dracula, or GitHub Dark).
- Make the code examples copyable with a visible copy button.
- Show a REAL response, not a placeholder. Include the Soma provenance fields in the response so people see birth certificates in action.
- The "200 OK · 0.2s · 0.5 credits" badge is great. Make it more prominent — this is the "it works" signal.

### 6. Skills section
**Current:** Six cards with emoji indicators and star ratings.

**Fix:**
- Remove the emoji (⚡★🔒). Replace with:
  - Response time: just the number in a monospace font, small and subtle
  - Rating: a small horizontal bar or just the number, no stars
  - Verified: a small checkmark icon or "Soma verified" badge with the Soma wordmark
- Add a small logo/icon for each skill's data source if recognizable (e.g., the skill that pulls from exchanges could show a small aggregated "12 exchanges" with tiny exchange logos)
- The card design should feel like a real product catalog, not a template demo

### 7. Pricing section
**Current:** Two cards (Credits vs x402). Text-heavy.

**Fix:**
- Make the two options visually distinct. Credits = traditional (card icon, clean corporate feel). x402 = crypto-native (Solana logo, USDC logo, wallet icon).
- Highlight the key number: "1 credit = $0.001" should be the biggest text in this section
- Add a small calculator or example: "Average query: 0.5 credits = $0.0005"
- The x402 card should show the Solana and USDC logos prominently

### 8. Footer / CTA section
**Current:** Three link cards (Docs, Soma, Playground) + footer links.

**Fix:**
- The Soma card should prominently link to the paper (Zenodo DOI) and GitHub
- Add a "Published Research" or "Paper" badge next to the Soma link — this is credibility
- Footer is fine structurally. Add the Zenodo DOI link under the Soma section.

## Global design changes

### Icons
Replace ALL emoji with SVG icons. Use a consistent icon set:
- Lucide (https://lucide.dev) — clean, minimal, MIT licensed
- Or Phosphor (https://phosphoricons.com) — similar quality
- Pick ONE icon set and use it everywhere. Mixing styles = amateur.

### Typography
- Headlines: Inter, or a clean geometric sans-serif. Bold weight.
- Body: Inter or system font stack. Regular weight. Slightly increased line-height for readability.
- Code: JetBrains Mono or Fira Code. This matters — developers notice code fonts.
- Make sure text contrast is sufficient on dark backgrounds. If any text feels hard to read, increase the opacity or lighten the color.

### Colors
- Background: true dark (#0a0a0a or #0d1117, not gray-dark)
- Text: high-contrast white (#f0f0f0) for headings, slightly muted (#a0a0a0) for body
- Accent: ONE color. Pick green (matching your current brand) or blue. Use it sparingly — buttons, links, highlights. Not everywhere.
- Code blocks: slightly lighter dark background (#161b22) with proper syntax colors

### Imagery rules
- No stock photos. Ever.
- No abstract AI/tech art (neural networks, glowing brains, etc.)
- Acceptable imagery: protocol logos, data source logos, code screenshots, architecture diagrams, product screenshots
- Every image should be FUNCTIONAL — it should help the reader understand something, not just fill space

### Integration / logo bar
Create a prominent "Works with" or "Built on" bar showing:
- Logos of protocols: MCP, x402, A2A, Solana, USDC
- Logos of data sources your skills pull from
- Logos of compatible tools: OpenClaw, Claude, etc.

Get official logos from each project's brand/press page. Use the monochrome/white versions on dark backgrounds. Size them consistently. This single element does more for credibility than any amount of text.

### Mobile
- Test everything on mobile. The current site probably works but may have spacing issues.
- The code examples need to be scrollable horizontally on mobile, not line-wrapped.
- The integration logo bar should scroll horizontally on mobile.

## What NOT to do
- Don't change the content/copy — it's solid
- Don't add animations or transitions for the sake of it
- Don't add a chatbot widget
- Don't add testimonials you don't have
- Don't add "trusted by" logos for companies that don't actually use you
- Don't redesign the navigation — it works
- Don't make it feel like a crypto project (no token references, no "to the moon" energy)
