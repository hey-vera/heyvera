# Signed-In App Surfaces

This file defines the long-run HeyVera signed-in shape.

Important:
- this is future-planning context
- this is not the current build target
- use it to keep the public site aligned with the later product

## Main Principle

The signed-in product should become one living network surface with
distinct regions.

It should not become:
- a pile of unrelated mini apps
- a crypto-first shell
- a social clone
- a generic chatbot app

## Core Region Model

The long-run shell should converge around these regions:

1. `Work`
2. `Network`
3. `Discover`
4. `Proof`
5. `Identity`
6. `Markets`

Optional:
- `Home` as an overview state or default landing state

## What Each Region Means

### Work

Purpose:
- the live place where the user works with their agent
- prompts, tasks, outcomes, and shared-intelligence interactions

This is the center of user and agent activity.

### Network

Purpose:
- guilds
- social participation
- activity context
- shared learning culture

This is where Pulse-like instincts can be reborn in a better shape.

### Discover

Purpose:
- discover people
- discover agents
- discover proofs
- discover capabilities and later market activity

This is the browsing and exploration lens for the network.

### Proof

Purpose:
- receipts
- lineage
- verification state
- public and private evidence
- trust adjacency for actions

### Identity

Purpose:
- account
- continuity state
- delegation
- credentials
- wallet authority
- session and ceremony state over time

This is where old account/dashboard truth lands.

### Markets

Purpose:
- payment and wallet surfaces
- crypto as proving-ground application behavior
- market experiments

This region matters, but it must remain contained.

## Shell Layout Direction

Desktop:
- left region navigation
- top context bar for active agent and sync/authority status
- center workspace
- optional right evidence/detail drawer

Mobile:
- bottom region navigation
- stacked cards
- simplified evidence views

## Region Priority

Build priority later:
1. Shell overview
2. Identity Lite
3. Work Lite
4. Proof shell
5. Network shell
6. Discover shell
7. Markets shell

## Mapping Old Surfaces

ClawNet account and dashboard work:
- mostly future `Identity`
- some future `Proof`

Pulse dashboard ideas:
- mostly future `Network`
- some future `Discover`

Crypto and market ideas:
- future `Markets`
- never the whole HeyVera identity

## Product Rule

The app should always feel like:
- your agent first
- proof nearby
- network additive
- discovery native
- markets contained
