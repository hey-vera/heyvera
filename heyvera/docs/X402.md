# x402 agent micropayments (Social)

Wave **14m/n/o** production path for HeyVera Social only (not Markets).

## Honesty

| Mode | When | What happens |
|------|------|----------------|
| `disabled` | `X402_ENABLED` ≠ `1` (default) | Status shows disabled; `POST /verify` and `POST /paid-ping` → **501** |
| `shape_only` | Enabled, no facilitator URL | Shape validation + durable receipt (`pending`); **`verified: false`**, **`settled: false`** |
| `facilitator` | Enabled + `X402_FACILITATOR_URL` | HTTP POST to facilitator `/verify`; receipt + honest `verified` / `settled` |

This API **never** reads, logs, or stores private keys / wallet secrets.

## Environment

| Variable | Required | Purpose |
|----------|----------|---------|
| `X402_ENABLED` | no | Exactly `1` enables the path; anything else = off |
| `X402_NETWORK` | no | e.g. `base-sepolia` or `base` (default `base-sepolia` when enabled) |
| `X402_FACILITATOR_URL` | no | Facilitator base URL (e.g. Coinbase CDP facilitator). Optional trailing `/verify` |
| `X402_PAY_TO` | no | **Public** recipient address returned on status (never a private key) |

See also `PRODUCTION-ENV.md`.

## Endpoints

### `GET /v1/social/x402/status` (public)

```json
{
  "enabled": true,
  "network": "base-sepolia",
  "mode": "shape_only",
  "payTo": "0x…",
  "note": "…"
}
```

### `POST /v1/social/x402/verify`

Body (any of `payload`, `payment`, or `amount` required for shape):

```json
{
  "payload": { "x402Version": 1, "paymentHeader": "…" },
  "amount": "0.01",
  "network": "base-sepolia",
  "idempotencyKey": "client-supplied-unique-key"
}
```

Also accepts header `Idempotency-Key`. Same key returns the stored receipt (idempotent).

### `POST /v1/social/x402/paid-ping` (Wave 14o product gate)

Authenticated Social product surface that **requires payment proof** when x402 is enabled.

| Mode | Behavior |
|------|----------|
| `disabled` | **501** `{ ok: false, reason: "payments off" }` |
| `shape_only` | Accepts shape payment + stores receipt `pending`; **200** with `settled: false`, `mode: "shape_only"` |
| `facilitator` | Calls facilitator verify; **200** only when verified (`settled: true`); otherwise **402** fail-closed |

```json
// success (shape_only)
{
  "ok": true,
  "action": "paid-ping",
  "pong": true,
  "mode": "shape_only",
  "settled": false,
  "verified": false,
  "status": "pending",
  "receiptId": "x402_…",
  "note": "product_gate:paid-ping used (shape_only; not settled)"
}
```

```json
// fail closed (facilitator, no valid payment)
{
  "ok": false,
  "action": "paid-ping",
  "reason": "payment not verified",
  "mode": "facilitator",
  "settled": false,
  "status": "failed"
}
```

Receipts from this endpoint use idempotency keys prefixed with `paid-ping:` and notes tagged `product_gate:paid-ping` so usage is auditable.

**UI:** Settings → Billing/Data and Pulse (AI) show **Test paid action** only when status reports enabled. Result copy is honest about settlement.

## Receipts

Table `social_x402_receipts`:

- `id`, `idempotency_key` (unique), `payload_hash`, `amount`, `network`
- `status`: `pending` | `verified` | `failed`
- `mode`, `note`, `raw_response` (optional facilitator JSON), `created_at`
