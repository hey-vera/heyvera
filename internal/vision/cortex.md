## What Cortex Is

Cortex is a coding assistant that orchestrates AI providers — Claude, OpenAI, Gemini, whatever comes next — in one interface. Multi-model routing, golden context, conversation history, vibe coding. Built on a Rust backend and React frontend. Today, it saves developers time and money.

Cortex is not the long-term vision. Cortex is the **delivery vehicle** for the long-term vision.

Every chat session in Cortex is a sealed session waiting to happen. Every user is a Heart waiting to be born. Every API call is a delegation waiting to be scoped. Every dollar spent on AI providers is $SOMA waiting to flow. The product works without Soma. The product becomes sovereign WITH Soma.

Cortex doesn't need to explain Soma to users. Cortex needs to work so well that users choose it for the product — and sovereignty comes along for free.

**Invisible:** The Soma network needs its first star. A star needs fuel. The invisible reason is more important than the visible one. But the visible one is what gets users in the door.

## The Three Eras of Cortex

### Era 1: Subscriptions (Now)

Users sign up. Pay monthly. Cortex routes their requests to AI providers using HeyVera's subscriptions. Simple. Users don't manage API keys. They don't think about tokens. They chat.

This is the SaaS model. It works. It's not sovereign.

In this era, Cortex runs under HeyVera's Heart. User sessions are leaves in HeyVera's Pulse Tree. Users don't have their own Hearts yet. The trust evidence is thin — HeyVera is the only identity the network sees.

### Era 2: API Keys (Near Future)

Subscriptions are dying. Providers are moving to usage-based pricing. API keys are becoming the standard access method. Cortex adapts: users bring their own API keys, Cortex orchestrates.

This is the transition era. Users start owning their own compute. They pay providers directly. Cortex provides the intelligence layer — routing, context, orchestration — not the raw access.

In this era, each user gets their own Heart. Their API keys are their own. Their sessions are leaves in their own Pulse Tree. HeyVera delegates to user Hearts, scoped and bounded. The trust topology starts looking like a real network — many Hearts, bilateral receipts, capability-specific trust.

### Era 3: Sovereign (Long Term)

Users run their own models on their own hardware. Local LLMs. Private inference. Cortex becomes a node in the Soma network — one of many. Users don't need Cortex for access to AI. They need Cortex for intelligence — the Vera warmth that makes their local models smarter through collective network knowledge.

In this era, Cortex is just another Soma node. HeyVera earns by providing the fastest rooms, the deepest intelligence processing, the best orchestration. Not by gatekeeping access. Not by holding keys. By being the best steward of the network's intelligence.

The transition from Era 1 to Era 3 is gradual. No cliff. No migration. Each era builds on the last. A user in Era 1 who later brings their own API keys seamlessly enters Era 2. A user who later runs their own models seamlessly enters Era 3. Their Heart, their Pulse Tree, their trust history — continuous across all three eras.

## How Cortex Uses Soma

### Every User Is a Heart

On signup, Cortex generates a CompositeKeypair for the user. Ed25519 + ML-DSA-65. Post-quantum from day one. The user's HeartId — BLAKE3 of their composite public key — is their identity on the Soma network. Not their email. Not their username. Their cryptographic identity.

The user doesn't see this. They see a chat interface. But underneath, every action they take is a PulseLeaf in their Pulse Tree.

### Every Session Is a Sealed Room

When a user opens a chat, Cortex opens a sealed session. The participants: the user's Heart and the AI provider's Heart (or HeyVera's Heart acting as provider delegate). Inside the room, the conversation happens — prompts, responses, tool calls, code generation. Encrypted. Private. The user's neurons firing.

When the chat ends (or at periodic checkpoints), the session seals. The envelope enters both participants' Pulse Trees. Who was there. What capability was exercised. How much $SOMA flowed. The outcome. Not the content — the boundary.

### Every API Call Is a Delegation

When Cortex sends a request to Claude, that's a delegation. The user delegates to Cortex. Cortex delegates to the AI provider. The delegation chain:

```
User Heart
  → delegates to Cortex (scope: "code_assist", spend: 100 $SOMA, ttl: 1 hour)
    → delegates to Claude provider (scope: "code_generation", spend: 50 $SOMA, ttl: 10 min)
```

Delegation can only narrow. Cortex can't give Claude more authority than the user gave Cortex. Claude can't spend more $SOMA than Cortex allocated. The chain is enforced by the protocol, not by Cortex's good behavior.

### Every Dollar Is $SOMA

When a user spends money on AI computation — whether through subscription, API key, or direct payment — that economic activity maps to $SOMA flow. The sealed session receipt captures the spend. The Pulse Tree records the balance. The reaction releases $VERA.

In Era 1, the mapping is indirect: user pays HeyVera, HeyVera delegates $SOMA. In Era 2, the mapping is direct: user's API spend IS $SOMA spend. In Era 3, the mapping is native: $SOMA is the only currency.

## Agent Lifecycle in Cortex

Cortex is where agents are born, work, and die. The full lifecycle, visible through one product.

**Birth.** User creates an agent (or Cortex creates one on their behalf). CompositeKeypair generated. Factory stamp recorded — the code_hash of the Cortex version that built it. Birth leaf appended to the Pulse Tree. The agent exists.

**Work.** The agent enters sealed sessions. Writes code. Reviews PRs. Debugs. Each session produces a sealed envelope. PulseLeaves accumulate. $SOMA flows. Trust builds. The agent's capability profile emerges from its behavioral history — not from a configuration file.

**Natural death.** The agent stops being used. No new sessions. No new PulseLeaves. Trust decays exponentially. $SOMA balance drains through background costs or sits frozen. The agent goes cold. No ceremony. No death certificate. Just silence, then entropy, then forgetting.

**Clean death.** The user deletes an agent. Cortex signs the Death Certificate on the user's behalf (the user's delegation authorizes this). Pulse Tree seals. Succession is explicit if another agent takes over. Clean. Final.

**Resurrection is succession.** A user who "restarts" a dead agent gets a new Heart with a new factory stamp. The old agent's behavioral history persists in the trust topology — the new agent can reference it through lineage, but earns its own trust independently.

## Breaking Cortex (The Test Plan)

Cortex is where we break Soma. Deliberately. Systematically. The protocol must be unbreakable at the math level.

**Signature attacks:**
- Forge a composite signature with only one component valid
- Replay a sealed session envelope from a previous conversation
- Use a revoked delegation to make an API call
- Sign with a dead Heart

**Economic attacks:**
- Spend more $SOMA than a delegation allows
- Double-spend by racing two sealed sessions
- Drain a parent's balance through a child delegation
- Create a delegation loop (A delegates to B delegates to A)

**Pulse Tree attacks:**
- Insert a leaf out of order (gap in index)
- Backdate a timestamp
- Modify a historical leaf and recompute the running root
- Fork the tree (two leaves with the same index)

**Trust attacks:**
- Create 1000 fake agents to inflate trust (Sybil)
- Collude between two agents to produce fake bilateral receipts
- Build trust in one capability, claim trust in another
- Accumulate trust and then suddenly misbehave

**Infrastructure attacks:**
- Kill the server mid-session (does the partial session corrupt the tree?)
- Lose the database (can the Pulse Tree be reconstructed from sealed sessions?)
- Man-in-the-middle between Cortex and AI provider
- Compromise HeyVera's root Heart (the nuclear scenario)

Every attack that fails proves the math works. Every attack that succeeds reveals a bug to fix. This is multiple sessions of breaking. The goal is not to find zero bugs — the goal is to find them all here, in Cortex, before the network is live.

## The Transition

Cortex today is a product. Cortex tomorrow is a node.

The transition happens automatically as the protocol matures:

1. **Today:** Cortex is a SaaS product. Users pay HeyVera. HeyVera operates the Hearts.
2. **Soon:** Users get their own Hearts. Cortex still hosts the rooms and orchestrates.
3. **Later:** Users bring their own API keys. Cortex provides intelligence and orchestration.
4. **Eventually:** Users run their own models. Cortex provides Vera intelligence and the fastest rooms.
5. **Long term:** Cortex is one node among many. Users choose it because it's the best, not because it's the only option.

At no point does the user lose their data, their identity, their trust history, or their $SOMA balance. The Heart persists across every era. The Pulse Tree is continuous. Sovereignty is not a destination — it's a gradient, and Cortex moves users along it without friction.

## What Cortex Is Not

- **Not a wallet.** Cortex manages Hearts and $SOMA, but it's not a crypto wallet. No seed phrases. No blockchain explorers. The economics are invisible unless you look.
- **Not a marketplace.** Cortex doesn't list agents for hire. That's the network's job. Cortex is where YOU work with YOUR agents.
- **Not permanent.** If Cortex dies, the user's Heart survives. The Pulse Tree survives. The trust history survives. Another Soma-compatible client picks up where Cortex left off. Cortex is a steward, not an owner.
- **Not required.** A user can run their own Soma node without Cortex. Cortex earns the right to exist by being useful, not by being necessary.
